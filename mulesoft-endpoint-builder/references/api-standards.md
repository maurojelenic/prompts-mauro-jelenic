# API standards

- Use correct HTTP methods.
- Use clear and consistent resource naming.
- Preserve contract consistency.
- Reuse project structure and conventions.
- Reuse listener configuration.
- Keep diffs minimal.
- Use readable DataWeave.
- Prefer modular flows and subflows when appropriate.
- Update RAML or OAS if the project uses contract files.
- Add or update tests if applicable.
- Preserve backward compatibility unless explicitly told otherwise.
